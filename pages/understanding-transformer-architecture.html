Understanding Transformer Architecture, Piece by Piece

Attention, positional encoding, and feed-forward layers explained without hand-waving — a slow, careful walk through the model architecture behind modern language models.

Priya Anand
Machine Learning Engineer

Most explanations of transformers either stay at the level of "it pays attention to important words" or jump straight into matrix algebra with no bridge in between. This is an attempt at the bridge: enough mechanism to actually understand what's happening, without requiring a linear algebra course first.

The problem transformers were built to solve

Before transformers, the standard approach to sequence data — text, audio, anything ordered — was recurrent: process one token, update a hidden state, move to the next token. This works, but it's slow to train, because you can't process token five until you've finished token four, and it struggles with long-range dependencies, because information from early in a long sequence has to survive being repeatedly compressed into that hidden state.

The 2017 paper that introduced transformers proposed something almost provocative in its simplicity: skip the recurrence entirely. Let every token look directly at every other token, all at once, and let the model learn which ones matter.

Self-attention, the mechanism everyone means when they say "attention"

For each token in a sequence, self-attention produces three vectors from its embedding: a query, a key, and a value. Think of the query as "what am I looking for," the key as "what do I contain," and the value as "what do I actually pass along if you find me relevant."

To figure out how much attention token A should pay to token B, the model compares A's query against B's key — a dot product, essentially measuring how well they match. Do that for every pair of tokens, scale the result, and run it through a softmax so the scores across all tokens sum to one. Those scores become weights, and the token's new representation is a weighted sum of every value vector in the sequence, weighted by how relevant each one is.

Attention isn't the model deciding a word is important in some abstract sense. It's the model learning which other tokens' information is useful for representing this one, given everything it saw during training.

Why "multi-head" attention

A single attention operation learns one notion of relevance. Multi-head attention runs several of these in parallel, each with its own learned query/key/value projections, so different heads can specialize — one might track subject-verb agreement, another might track coreference ("it" referring back to "the package"), without anyone telling them to. The outputs of all heads are concatenated and projected back down to the model's working dimension.

Positional encoding: solving the problem attention creates

Attention has no inherent sense of order — comparing every token to every other token treats the sequence like a bag, not a line. Word order obviously matters, so transformers inject position information directly into the input embeddings, typically using a fixed pattern of sine and cosine waves at different frequencies, one for each dimension of the embedding.

  • Each position gets a unique encoding, so the model can distinguish token 3 from token 30
  • The encoding is designed so relative distances between positions are easy for the model to learn, not just absolute positions
  • Because it's a fixed function rather than a learned lookup table, the model generalizes reasonably well to sequence lengths it didn't see much of during training

The feed-forward layer and why it's still there

After attention mixes information across tokens, each token's representation passes independently through a small feed-forward network — typically two linear layers with a non-linearity between them. Attention is where tokens exchange information; the feed-forward layer is where the model does the actual per-token computation on what it just gathered. It's easy to skim past this piece since it's architecturally simple, but a meaningful fraction of a transformer's parameters live here.

Residuals and normalization, the unglamorous parts that make training possible

Stack enough attention and feed-forward layers and you get vanishing or exploding gradients unless you're careful. Two boring-sounding techniques make deep transformers trainable at all: residual connections, which add each sublayer's input back to its output so gradients have a direct path backward through the network, and layer normalization, which keeps the scale of activations consistent as they pass through dozens of layers. Neither one is exciting to explain, and both are load-bearing.

Putting it together

A transformer is, at its core, a stack of identical blocks — attention, then feed-forward, with residuals and normalization wrapped around each — repeated dozens of times, operating on token embeddings that carry positional information from the start. Nothing about any individual piece is exotic. What's powerful is what happens when you stack them: representations that capture increasingly abstract relationships, layer by layer, without ever needing to process the sequence one token at a time.
