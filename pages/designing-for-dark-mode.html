Designing for Dark Mode Without Breaking Everything

Dark mode is not light mode with the colors inverted. Contrast, elevation, and color all behave differently once the background goes dark — here's how to design for it.

Priya Anand
Machine Learning Engineer

The naive approach to dark mode is to invert everything: white backgrounds become black, black text becomes white, and every other color gets flipped or darkened by some formula. It technically works, in the sense that the page loads and nothing crashes. It also tends to look muddy, produce jarring pure-white text that vibrates against a pure-black background, and lose the visual hierarchy the light theme had. Dark mode done well is a separate design, informed by the light theme, not derived from it mechanically.

Never use pure black, and rarely use pure white

Pure black (#000000) against pure white text creates the highest possible contrast ratio, which sounds good until you notice it in practice: high-contrast text on a pure black background produces a halation effect, especially on OLED screens, where text appears to glow and smear slightly, which is genuinely more tiring to read than a softer combination.

A near-black background — something in the range of a very dark charcoal or navy, not true black — paired with an off-white text color (not pure white) reads more comfortably and, done right, still comfortably clears accessibility contrast requirements.

Dark mode readability is not maximized by maximum contrast. It's maximized by comfortable contrast, which is a slightly lower and much more forgiving number.

Elevation works backwards in the dark

In a light theme, raised surfaces — cards, modals, dropdowns — typically get darker shadows to imply they're floating above the background. In a dark theme, shadows barely register against a dark background, so elevation has to be communicated differently: raised surfaces should generally get lighter, not darker, moving toward a slightly brighter shade of the base color as they get closer to the "top" of the visual stack. This mirrors how light actually behaves — surfaces closer to an implied light source appear lighter.

Saturated colors get more aggressive against dark backgrounds

A saturated blue or red that looks calm on a white background can look aggressively bright against a dark one, because the eye's perception of a color's intensity is relative to what surrounds it. The fix is usually to desaturate and slightly lighten accent colors for dark mode rather than reusing the exact same hex values from the light theme — the same brand color, adjusted, not abandoned.

Build it with CSS custom properties from the start

Retrofitting dark mode onto a codebase full of hardcoded hex values is painful. Defining a full palette as CSS custom properties, then overriding that set of variables under a data-theme or class selector, keeps every component automatically correct without touching component-level CSS at all:

:root {
  --bg: #F5F4EF;
  --text: #171A1F;
}
[data-theme="dark"] {
  --bg: #14161C;
  --text: #EDEBE4;
}
body { background: var(--bg); color: var(--text); }

Respect the system preference, but let people override it

Reading prefers-color-scheme and defaulting to it is good manners — someone who has already told their operating system they prefer dark mode shouldn't have to tell every website separately. But always provide an explicit toggle too, store the choice, and let it override the system preference, because plenty of people want a different theme for a specific site than they use everywhere else, particularly for reading-heavy pages late at night.

Test it on real content, not a placeholder screenshot

Dark mode bugs hide in the content that designers don't usually screenshot: a chart with colors chosen for a white background, an embedded image with a white border baked in, a code block syntax theme that assumes a light background. Before calling a dark theme done, look at it with real long-form content, real data visualizations, and real user-generated content, not just the marketing page it was designed on.
