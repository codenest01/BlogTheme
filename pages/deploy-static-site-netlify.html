Deploying Your First Static Site on Netlify

From a folder on your laptop to a live URL with a custom domain — a step-by-step walkthrough for people who've never deployed anything before.

Priya Anand
Machine Learning Engineer

If you've built a static site — plain HTML, CSS, and JavaScript, no server required — getting it online should take about ten minutes. It usually doesn't, the first time, because most guides assume you already know what a build command is. This one doesn't assume that.

Step 1: get your project into a Git repository

Netlify deploys from a Git repository, not from a folder on your computer, so the first step is making sure your project actually lives in one. If you haven't already:

  1. Create a new repository on GitHub (or GitLab, or Bitbucket — Netlify supports all three)
  2. In your project folder, run git init if it isn't already a repository
  3. Add your files, commit them, and push to the new repository's main branch
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/your-username/your-repo.git
git push -u origin main

Step 2: connect the repository to Netlify

From your Netlify dashboard, choose to add a new site from an existing Git repository, authorize access to your Git provider if you haven't already, and select the repository you just pushed. Netlify will scan it and propose build settings automatically.

Step 3: set the build settings correctly

For a plain HTML/CSS/JS site with no framework and no build step, the settings are simpler than most tutorials make them sound:

  • Build command: leave this blank — there's nothing to compile
  • Publish directory: the folder containing your index.html, often the repository root (a single dot, ".")
  • Branch to deploy: main, or whichever branch you want to go live
If your project has no framework and no bundler, you almost certainly want an empty build command. A build command is for compiling something — there's nothing to compile in a plain static site.

Step 4: deploy and check the preview URL

Click deploy, and Netlify will hand you a randomly generated URL — something like effervescent-narwhal-8f2a1c.netlify.app — that's already live on the public internet. This is a real deployment, not a preview in the limited sense; if you share that URL right now, anyone can visit it.

Step 5: point a custom domain at it

If you own a domain already, Netlify's domain settings will ask you to either delegate the domain's nameservers to Netlify (the simpler option, if you're comfortable with it) or add specific DNS records at your existing registrar — typically an A record for the root domain and a CNAME for the www subdomain. Either path, Netlify provisions a free TLS certificate automatically once the DNS is verified, usually within a few minutes.

A note on netlify.toml

You don't need a netlify.toml file for a basic deploy — the dashboard settings are enough. It becomes useful once you want redirects, custom headers, or to check your build settings into version control instead of managing them by hand in the dashboard, so your configuration travels with your code.

Step 6: every future push deploys automatically

From here, the workflow is just Git. Push a commit to your connected branch, and Netlify rebuilds and redeploys automatically, typically within a minute. There's no separate "deploy" step to remember — your deployment history becomes your commit history, which also means rolling back a bad change is as simple as reverting to a previous deploy from the dashboard.
